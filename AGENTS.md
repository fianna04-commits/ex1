# FACEFORM project

This is a static Hebrew/RTL personal face styling app, published from `main` to GitHub Pages. Runtime files are `index.html`, `styles.css`, and classic `app.js`, with no build, external code dependencies, AI, APIs, or backend. It must also work when opening index.html directly. Reference pictures now load from reviewed official cosmetics-brand image URLs, as explicitly requested by the user. Focus on hair, hair color, makeup, eyebrows, glasses, earrings and hats; do not add other clothing recommendations.

## Delivery workflow

## Personal photos

Display personal photos locally using temporary object URLs. Do not analyze them, upload them, or include them in Git, favorites, recommendation-card exports, telemetry, or server storage. Recommendations use manually selected attributes. The user subsequently requested real online styling references instead of repeated schematic portraits: use licensed photographic examples with explicit attribute audits. ## Design and behavior

Use cream, black, powder pink and beige with an editorial beauty-magazine style. Maintain mobile layouts, Hebrew RTL, visible keyboard focus, reduced-motion support, and named color choices. Keep three rule-based recommendation variants (Natural, Elegant, Trendy), optional questionnaire fields, instant updates, local favorites, and PNG recommendation-card export. Makeup preferences must take priority over style/event suggestions. Keep saved photos out of localStorage. Existing VIBE favorites under their old storage key must not be overwritten.

The audience is women only. Respect known face structure, hair length and texture as recommendation eligibility constraints. Preserve the selected current hair color; alternative dye colors remain optional suggestions. Do not force three different haircuts or repeat a photo merely to fill result slots. The user explicitly selected verified matches only: all known selected attributes must have a recorded match. Do not offer partial-information matching or a relaxation action. Normalize legacy favorite modes to strict matching, and do not let legacy API options bypass verification. If no eligible photo exists, show a clear message and a targeted external-search link; external search results are not verified by the app. Never infer skin undertone or facial structure from stock photos. Unknowns remain unknown. Keep the full nine-attribute + event + style breakdown accessible for each look. Filter gallery, styles, favorites and exports consistently.

Keep all eight style directions distinct in hair finish, makeup/accessory treatment and optional palette accents. 2026 trend claims must cite verified primary/editorial sources in the UI. Trends must not override no-makeup, length, texture, or current-color preferences. Reference images illustrate directions; never label them as photographs taken at 2026 shows unless their actual provenance supports that claim. Preserve no-photo PNG exports and explicit empty states when no eligible reference exists.

The user restricts image sources to Pinterest or official cosmetics-brand publications. Do not restore the former Pexels library. Keep publisher attribution and source links; do not imply brand endorsement or claim a reuse license that was not supplied. Use no-referrer image requests and anonymous CORS when exporting a reference, with a text/palette fallback if the external image fails. Personal photos remain local and are never exported. Pinterest Pin verification was blocked by a declined browser-origin permission; do not evade that restriction or label uninspected Pins as verified. Targeted Pinterest search links remain the approved fallback and are not represented as curated or verified results. Keep separate earrings, glasses and hats recommendations with explanations and category-specific searches. Official brand how-to links are guidance, not full-profile photo matches, and are omitted for no-makeup preferences.
